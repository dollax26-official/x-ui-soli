# x-ui روی Railway — یک پورت، چند نودی (پنل مرکزی + نودها)

[English](./README.md) | فارسی

پنل [3x-ui](https://github.com/mhsanaei/3x-ui) نسخهٔ v3.8.5 را پشت یک reverse proxy
با nginx روی **یک پورت واحد Railway** اجرا می‌کند؛ هم پنل وب و هم اینباند
VLESS/WebSocket از همان یک دامنهٔ HTTPS در دسترس‌اند.

علاوه بر این، این پکیج اجازه می‌دهد **چند دیپلوی از همین ریپو** به هم وصل شوند:
یک **پنل مرکزی** بقیه را به‌عنوان **نود** مدیریت می‌کند. این کار از قابلیت
داخلی چند-نودی 3x-ui استفاده می‌کند و **ظاهر و کد پنل هیچ تغییری نکرده است**.

## فایل‌ها

| فایل | نقش |
| ---- | ---- |
| `Dockerfile` | ساخت ایمیج (3x-ui + nginx + اسکریپت کمکی). |
| `nginx.conf.template` | مسیردهی تک‌پورتی (`/managepanel/`، `/sub/`، `/`). |
| `start.sh` | اجرای پنل و nginx؛ nginx روی `$PORT` رِیلوی گوش می‌دهد. |
| `node-link.sh` | ساخت توکن API نود و چاپ مقادیری که در پنل مرکزی وارد می‌کنید. |

---

## ۱. دیپلوی

1. از این فایل‌ها یک ریپو بسازید (یا همین ریپو را دیپلوی کنید).
2. در Railway: **New Project → Deploy from GitHub repo** و انتخاب ریپو؛ `Dockerfile`
   خودکار تشخیص داده و بیلد می‌شود.
3. **Settings → Networking → Generate Domain** را برای سرویس بزنید. پنلی که دامنهٔ
   عمومی ندارد از پنل مرکزی قابل دسترسی نیست، پس برای **هر** نودی که می‌خواهید
   انجام دهید.
4. *(توصیه)* یک **Volume** روی مسیر `/etc/x-ui` وصل کنید؛ در غیر این صورت با هر
   Redeploy کاربران/اینباندها/تنظیمات/توکن‌ها پاک می‌شوند.

### اولین ورود

```
https://<دامنهٔ-شما>.up.railway.app/managepanel/
```

یوزر/پس پیش‌فرض `admin` / `admin` است — فوراً از **Settings → Panel** تغییرش دهید.

### ساخت اینباند

یک اینباند **VLESS** با **Listen Port `8080`** بسازید (چون nginx مسیر `location /`
را به آن فوروارد می‌کند)، Network = **ws**، Security = **none**، Path دلخواه (مثلاً `/cdn`).

```
vless://<UUID>@<دامنهٔ-شما>.up.railway.app:443?encryption=none&security=tls&sni=<دامنهٔ-شما>.up.railway.app&fp=chrome&type=ws&host=<دامنهٔ-شما>.up.railway.app&path=%2Fcdn#MyConfig
```

## ۲. چند-نودی (وصل کردن پنل‌ها به هم)

```
                  ┌───────────────────────────────┐
   کلاینت‌ها ───► │  پنل مرکزی (Master)            │
                  │  https://central.up.railway.app │
                  │  /managepanel/                 │
                  └──────────────┬────────────────┘
                                 │ HTTPS + API token
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
       ┌────────────┐     ┌────────────┐     ┌────────────┐
       │  نود A     │     │  نود B     │     │  نود C     │
       │  inbound   │     │  inbound   │     │  inbound   │
       └────────────┘     └────────────┘     └────────────┘
        اینباند VLESS/WS روی 8080 پشت همان یک پورت عمومی
```

پنل مرکزی هر نود را **پول** می‌کند و API پنل نود را در این آدرس صدا می‌زند:

```
<scheme>://<address>:<port><basePath>panel/api/...
```

چون این پکیج پنل (و `/panel/api/...` آن) را زیر `/managepanel/` سرو می‌کند، مقدار
فیلدهای نود همیشه این‌هاست:

| فیلد در «Add node» | مقدار برای یک نود Railway |
| ------------------ | ------------------------- |
| **Name** | هر نامی، مثلاً `de-fra-1` |
| **Scheme** | `https` |
| **Address** | دامنهٔ نود، مثلاً `node-xxx.up.railway.app` (بدون `https://`) |
| **Port** | `443` |
| **Base path** | `/managepanel/` |
| **API token** | توکنی که **روی خود نود** ساخته می‌شود (مرحلهٔ A) |
| **TLS verify** | `verify` |
| **Inbound sync** | `all` (یا `selected`) |

### مرحلهٔ A — روی نود: ساخت API key

پنل نود را در `https://<دامنهٔ-نود>/managepanel/` باز کنید، سپس یکی از دو راه:

- **از رابط کاربری:** *Settings → API Tokens → create* با scope = `admin` (یا
  `node-sync`). **همان لحظه کپی کنید** — فقط یک‌بار نمایش داده می‌شود.
- **اسکریپت:** در Shell سرویس اجرا کنید: `bash /node-link.sh` — توکن را می‌سازد و
  بلوک آمادهٔ کپی چاپ می‌کند:

  ```
  Scheme:    https
  Address:   node-xxx.up.railway.app
  Port:      443
  Base path: /managepanel/
  API token: <the token>
  ```

  (در فایل `/etc/x-ui/node-connection.txt` هم ذخیره می‌شود.)

### مرحلهٔ B — روی پنل مرکزی: چسباندن توکن + آدرس

پنل مرکزی → **Nodes → Add node** و مقادیر جدول بالا را وارد و **Test/Add** بزنید.
وقتی نود **online** شد، پنل مرکزی نسخه، CPU/RAM، آپ‌تایم و ترافیک نود را نشان
می‌دهد و تغییرات اینباند/کلاینت را روی آن اعمال می‌کند.

> خود نود هم می‌تواند نودهای بعدی را مدیریت کند؛ پنل مرکزی آن‌ها را به‌صورت
> زیرنودهای *transitive* و فقط-خواندنی نشان می‌دهد.

### اختیاری: mTLS به‌جای توکن

حالت **TLS verify** نود را روی `mtls` بگذارید (هر دو طرف `https`)، CA نودِ پنل
مرکزی را (Nodes → *Get CA*) در تنظیمات *trusted CA* نود بچسبانید و نود را ری‌استارت کنید.

## ۳. متغیرهای محیطی

| متغیر | پیش‌فرض | کاربرد |
| ----- | ------- | ------ |
| `PORT` | `3000` | پورتی که nginx روی آن گوش می‌دهد؛ Railway خودکار تنظیم می‌کند. |
| `NODE_PUBLIC_ADDRESS` | `$RAILWAY_PUBLIC_DOMAIN` | آدرسی که `node-link.sh` چاپ می‌کند. |
| `NODE_TOKEN_NAME` | `central` | نام توکنی که `node-link.sh` می‌سازد. |

Target port در Railway: چون nginx روی `$PORT` گوش می‌دهد، دامنهٔ ساخته‌شده مستقیم
وصل می‌شود. اگر `PORT` تزریق نشد، Target port سرویس را `3000` بگذارید.

---

## ۴. چه چیزی نسبت به نسخهٔ اصلی تغییر کرده

فقط همان مقدار لازم برای دسترسی‌پذیری و اتصال نودها. **پنل دست‌نخورده است.**

- `start.sh` — nginx حالا روی `$PORT` رِیلوی می‌نشیند (`${PORT:-3000}`) به‌جای
  عدد ثابت 3000، تا دامنهٔ عمومی همیشه به آن برسد.
- `Dockerfile` — فایل `node-link.sh` هم داخل ایمیج کپی می‌شود.
- `node-link.sh` — فایل کمکی جدید و اختیاری.

بقیهٔ چیزها (مسیرهای `nginx.conf.template`، تنظیمات پنل، اینباند روی 8080) بدون
تغییر مانده‌اند.

---

## ۵. رفع اشکال

- **نود offline است** → بررسی کنید: نود دامنهٔ عمومی دارد؛ Address بدون scheme است؛
  Port = `443`؛ Base path = `/managepanel/`؛ توکن کامل کپی شده. باز کردن
  `https://<دامنهٔ-نود>/managepanel/` در مرورگر باید صفحهٔ ورود را نشان دهد.
- **پیام "speaks HTTP, not HTTPS"** → Scheme آن نود را `http` بگذارید.
- **توکن بعد از Redeploy از کار افتاد** → Volume روی `/etc/x-ui` ندارید و دیتابیس
  (و توکن) ریست شده است. Volume را وصل کنید یا توکن تازه بسازید.
